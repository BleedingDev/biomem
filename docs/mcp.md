# biomem MCP adapter

The biomem MCP adapter exposes six local tools over standard input/output. It
does not load a memory model or open a `.bdbm` file. Every operation goes to the
already-running biomem daemon at `http://127.0.0.1:8766`, so MCP clients,
browser extensions, the CLI, and the desktop application observe the same
authoritative state.

```text
MCP host ── stdio ── biomem-mcp ── HTTP v1 loopback ── biomem daemon
```

Memory text, embeddings, and computation remain on the machine. The adapter
has no remote transport, telemetry, model download, or fallback database.

## Prerequisites

1. Install biomem with its MCP dependency.
2. Start `biomem-server` and leave it running.
3. Confirm that the daemon HTTP port is available (normally `8766`).

For an installed package, include the `mcp` extra:

```shell
pip install "biomem-memory[mcp]"
```

For an editable source checkout, run this from the `src` directory:

```shell
pip install -e ".[mcp]"
```

The base `biomem-memory` installation intentionally does not install the MCP
SDK. In that installation, `biomem-mcp` exits with a clear missing-dependency
error until the `mcp` extra is installed. Installing the `all` extra also
includes MCP support.

The adapter requires the official Python MCP SDK version `2.1.1`. Its command
is `biomem-mcp`. Hosts must launch it as a local stdio process; do not configure
it as an HTTP or SSE server.

If the daemon uses a non-default WebSocket port, set `BIOMEM_HTTP_PORT` to that
port plus one. The value must be an integer from 1 through 65535. The host is
fixed to `127.0.0.1` and cannot be redirected to another machine.

## Host configuration

Use the equivalent of this placeholder configuration in a local MCP host:

```json
{
  "mcpServers": {
    "biomem": {
      "command": "biomem-mcp",
      "args": [],
      "env": {
        "BIOMEM_HTTP_PORT": "8766"
      }
    }
  }
}
```

Remove the `env` object when the default port is in use.

## Tools

| Tool | Purpose | Bounds |
|---|---|---|
| `biomem_status` | Validate daemon identity, protocol, version, and readiness | No arguments |
| `biomem_store` | Store a durable key/value record | Key 1–16,384 characters; value 1–32,768 |
| `biomem_retrieve` | Recall associated records | Query 1–16,384; `top_k` 1–20 |
| `biomem_search` | Semantic search in `both`, `stm`, or `ltm` | `top_k` 1–50 |
| `biomem_list` | Page stable records from `both`, `stm`, or `ltm` | Limit 1–100; cursor at most 512 characters |
| `biomem_graph` | Read a bounded `stm` or `ltm` graph | Threshold 0–1; maximum 250 nodes |

All tool schemas reject unknown arguments. Read tools are marked read-only and
closed-world. `biomem_store` is non-destructive but is intentionally not marked
idempotent: a caller must not retry an uncertain write automatically.

MCP writes include local provenance generated by the adapter:

- `source_class`: `mcp`
- `origin`: `local-mcp-stdio`
- `session_id`: a new opaque `mcp:<uuid>` for each adapter process

The daemon remains responsible for timestamps, stable memory identity,
reinforcement decisions, persistence, and migrations.

## Security and failure behavior

The adapter ignores proxy environment variables, rejects redirects, applies
finite connection/read deadlines, and caps request and response sizes. Each
command is attempted once. It validates the complete HTTP v1 health response
before sending a command, including `product: "biomem"`, protocol version `1`,
HTTP transport, a non-empty product version, and `ready: true`.

Tool failures use a bounded code such as `SERVICE_UNAVAILABLE`,
`PROTOCOL_MISMATCH`, `MODULE_INACTIVE`,
`PAYLOAD_TOO_LARGE`, `DEADLINE_EXCEEDED`, or `INTERNAL_ERROR`. Daemon exception
details, tool arguments, results, and memory text are never logged.
Standard output is reserved exclusively for MCP frames; diagnostics go to
standard error.

## Troubleshooting

- `SERVICE_UNAVAILABLE`: start `biomem-server`, then check the configured HTTP
  port. The adapter never creates a private fallback memory.
- `PROTOCOL_MISMATCH`: another local process may own the port, or the daemon may
  be an incompatible version. Check `GET /api/health` locally.
- `MODULE_INACTIVE`: resume or activate biomem in the desktop application.
- `PAYLOAD_TOO_LARGE`: reduce the input or requested page/graph size.

## Removal

Delete the `biomem` MCP server entry from the host configuration and restart
the host. Removing the adapter does not delete or migrate biomem data because
the adapter owns no memory files.
